프로젝트를 진행하던 시점에 디자이너의 부재로 화면 설계부터 퍼블리싱까지 내가 빠르게 끌고 가야 했다.  
기획 문서만 보고 바로 코드를 작성하던 방식은 처음엔 빨랐지만, 수정 라운드가 쌓일수록 오히려 시간이 더 들고 화면 일관성도 쉽게 흔들렸다.

그래서 먼저 Figma Make로 초안 디자인을 만든 뒤, Figma Design 프로젝트에서 실제 화면 구조를 정리했다.  
그리고 이 설계를 코드로 옮기는 구간에서 Cursor MCP를 붙여 React + Tailwind CSS 기반으로 소스화하는 방식을 선택했다.

내가 기대한 건 단순 자동 생성이 아니라, "설계(Figma)와 구현(Cursor) 사이 왕복 비용을 줄여 퍼블리싱 과정을 단축하는 것"이었다.

## 관련 개념 정리

### 왜 Figma와 Cursor MCP를 같이 썼는가

Figma는 화면 구조와 컴포넌트 관계를 시각적으로 정리하기 좋고, Cursor는 실제 코드 작성/수정 속도를 높이는 데 강점이 있다.  
두 도구를 연결하면 "디자인 확정 -> 퍼블리싱 반영 -> 검수" 흐름이 짧아진다.

Figma와 MCP를 연동할 수 있는 AI 도구는 많았지만, 회사에서 Cursor를 공식 지원해주고 있어서 현실적인 도입 장벽이 가장 낮았다.  
실제로 팀 단위로 같은 도구를 쓰니 프롬프트 자산과 작업 방식이 빨리 공유됐고, 이 점이 생각보다 크게 체감됐다.

- **Figma 역할**: 화면 설계, 컴포넌트 구조 정의, 레이아웃 기준점 관리
- **Cursor MCP 역할**: 설계 내용을 바탕으로 코드 생성/수정, 반복 작업 자동화

### 이 방식이 필요한 이유

디자이너가 없는 상황에서는 화면 품질과 개발 속도를 동시에 챙기기가 생각보다 어렵다.  
특히 화면 수가 늘어나면 버튼, 카드, 폼 같은 반복 UI가 급격히 늘어나서 퍼블리싱 피로도가 빠르게 올라갔다.

이때 Figma에서 먼저 기준을 잡고 Cursor MCP로 퍼블리싱 소스를 만드는 방식은 다음 장점이 있었다.

- 화면 일관성을 유지하기 쉬움
- React 컴포넌트 재사용 구조를 초반부터 잡기 쉬움
- Tailwind 유틸리티 클래스 기반으로 빠른 수정이 가능함
- 수동 마크업 반복 작업이 줄어 퍼블리싱 리드타임이 짧아짐

### 기존 방식과 비교

| 방식                        | 장점                                  | 단점                             |
| --------------------------- | ------------------------------------- | -------------------------------- |
| 바로 코드 작성              | 초기 속도가 빠름                      | 반복 수정 많음, 화면 일관성 저하 |
| Figma 설계 후 수동 퍼블리싱 | 품질 관리 용이                        | 구현 시간이 길어질 수 있음       |
| Figma + Cursor MCP 연동     | 설계/구현 왕복 비용 감소, 생산성 향상 | 프롬프트 품질과 검수 기준이 필요 |

## 실제 적용

### 적용 전

- 디자이너 부재로 화면 의사결정이 개발 단계에서 반복됨
- 동일 UI를 화면마다 다시 작성해 퍼블리싱 비용 증가
- 기획 변경 시 수정 범위 예측이 어려움

### 적용 방법

실제 작업은 아래 순서로 진행했고, 이 흐름이 정착된 뒤부터 구현 체감 속도가 확실히 달라졌다.

1. **Figma Make로 UI 초안 생성**
2. **Figma Design 프로젝트에서 컴포넌트/화면 구조 정리**
3. **Cursor MCP 연동 후 React + Tailwind CSS 코드화**
4. **컴포넌트 단위로 분리하고 공통 UI 재사용 구조로 정리**

퍼블리싱 단계만 보면, 기존과 비교해 작업 흐름이 단순해졌다.

| 구분             | 기존 퍼블리싱 방식              | 연동 후 방식                      |
| ---------------- | ------------------------------- | --------------------------------- |
| 화면 구현 시작점 | 기획 문서/캡처 기반 수동 마크업 | Figma 컴포넌트 기준으로 코드 생성 |
| 수정 루프        | 코드 수정 -> 브라우저 확인 반복 | Figma 기준 수정 -> Cursor 반영    |
| 반복 UI 처리     | 화면마다 재작성                 | 공통 컴포넌트 재사용              |
| 결과             | 구현 편차 큼, 시간 증가         | 품질 편차 감소, 소스화 속도 향상  |

예를 들어, Figma에서 정리한 카드 UI를 Cursor로 퍼블리싱할 때 아래처럼 React 컴포넌트로 소스화했다.

```tsx
type SummaryCardProps = {
  title: string;
  value: string;
  description?: string;
};

export function SummaryCard({ title, value, description }: SummaryCardProps) {
  return (
    <article className="rounded-xl border border-zinc-200 bg-white p-4 shadow-sm dark:border-zinc-700 dark:bg-zinc-900">
      <h3 className="text-sm font-medium text-zinc-500 dark:text-zinc-400">
        {title}
      </h3>
      <p className="mt-2 text-2xl font-semibold text-zinc-900 dark:text-zinc-100">
        {value}
      </p>
      {description ? (
        <p className="mt-1 text-xs text-zinc-500 dark:text-zinc-400">
          {description}
        </p>
      ) : null}
    </article>
  );
}
```

Cursor MCP를 사용할 때는 "디자인 의도 -> 컴포넌트 책임 -> Tailwind 규칙"을 같이 전달하도록 프롬프트를 작성했다.  
처음에는 결과 편차가 있었지만, 이 기준을 반복해서 맞추자 출력 품질이 점점 안정됐다.

개인적으로 가장 크게 체감한 변화는 "퍼블리싱 시작 전 고민 시간"이 줄었다는 점이었다.  
예전에는 화면마다 클래스 구조를 처음부터 설계했는데, 연동 후에는 Figma 구조를 기준으로 바로 컴포넌트화할 수 있었다.

### 적용 후

- 화면 설계와 퍼블리싱 사이 전환 비용이 줄어 개발 속도가 눈에 띄게 좋아졌다.
- 반복 UI를 컴포넌트화하면서 React 재사용성이 확실히 올라갔다.
- Tailwind 기준이 정리되니 스타일 수정 범위를 예측하기 쉬워졌다.
- 기획 변경이 생겨도 Figma에서 먼저 조정하고 코드에 반영하는 흐름이 자연스럽게 자리잡았다.
- 결과적으로 퍼블리싱 병목(수동 마크업/반복 수정)이 줄어 전체 일정이 훨씬 안정적이었다.

## 적용 후기

### 좋았던 점

- AI 도구를 활용하면서 초기 화면 제작 시간이 확실히 짧아졌다.
- 디자이너가 없더라도 최소 품질의 UI 기준을 지킬 수 있었다.
- 반복 퍼블리싱 작업이 줄어서 기능 구현에 집중하기 쉬웠다.
- 같은 화면 수를 구현해도 퍼블리싱 소요 시간이 줄어 릴리스 준비가 빨라졌다.
- 생산성 향상을 직접 체감하고 나니, MCP/에이전트 워크플로우 같은 다른 AI 기술도 더 적극적으로 보게 됐다.

### 아쉬웠던 점

- 자동 생성 코드 품질이 항상 일정하지 않아 최종 검수가 필수였다.
- 프롬프트를 구체적으로 작성하지 않으면 구조가 쉽게 흔들렸다.
- Tailwind 클래스가 과도하게 길어져 가독성이 떨어지는 경우가 있었다.

### 추천하는 상황

- 디자이너 리소스가 부족한 초기 프로젝트
- 화면 수가 빠르게 늘어 퍼블리싱 속도가 중요한 경우
- React 컴포넌트 재사용 구조를 초기에 잡고 싶은 팀

## 마무리

이번 경험을 돌아보면, Figma와 Cursor MCP 연동은 "디자인 없는 개발"을 대체한다기보다 설계와 구현 사이 간격을 줄여주는 현실적인 방법이었다.  
특히 퍼블리싱 과정을 줄여야 하는 상황에서 효과가 컸고, AI 생산성을 제대로 살리려면 설계 기준과 검수 규칙을 함께 가져가야 한다는 걸 배웠다.  
앞으로도 단일 도구에 머물지 않고, 실무에 적용 가능한 다른 AI 기술들을 계속 실험해볼 생각이다.
