## 달라진 점

### React Compiler

React 19에서는 새로운 **React Compiler**가 도입되어 함수형 컴포넌트의 성능 최적화를 자동으로 수행한다.
기존에는 불필요한 리렌더를 막기 위해 개발자가 직접 `useMemo`, `useCallback`, `React.memo` 등을 사용하는 경우가 많았는데 Compiler는 이 부담을 줄여준다.

- `useMemo`, `useCallback` 없이도 불필요한 재렌더를 줄이는 방향
- props/state 변경 여부를 분석해 변화가 없으면 컴포넌트를 재사용
- 의존성 배열을 사람이 관리하지 않아도 되도록(또는 줄이도록) 유도
- React의 memoization / re-render control을 **컴파일 타임에 자동 처리**하는 접근

#### 예시 코드

```tsx
// React 18 스타일(개발자가 최적화 포인트를 직접 관리)
import React, { useCallback } from "react";

export const MyComponent = React.memo(({ value }: { value: string }) => {
  const handleClick = useCallback(() => {
    console.log(value);
  }, [value]);

  return <button onClick={handleClick}>Click me</button>;
});
```

```tsx
// React 19에서 지향하는 형태(의도는 단순하게, 최적화는 컴파일러가 돕는 방향)
export function MyComponent({ value }: { value: string }) {
  function handleClick() {
    console.log(value);
  }

  return <button onClick={handleClick}>Click me</button>;
}
```

### useOptimistic Hook

`useOptimistic`는 **서버 응답을 기다리는 동안** UI를 먼저 업데이트(낙관적 업데이트)할 수 있게 도와주는 훅이다.

- 댓글/좋아요/장바구니 추가처럼 “성공할 확률이 높고 즉시 반응이 중요한 UI”에 적합
- 실패 시 롤백(원복) 전략을 같이 고려해야 함

#### 예시 코드(낙관적 댓글 추가)

```tsx
import { useOptimistic, useState } from "react";

type Comment = { id: string; text: string };

async function createCommentOnServer(text: string) {
  // 서버 호출(예시)
  await new Promise((r) => setTimeout(r, 500));
  return { id: crypto.randomUUID(), text };
}

export default function CommentForm() {
  const [comments, setComments] = useState<Comment[]>([]);

  const [optimisticComments, addOptimistic] = useOptimistic(
    comments,
    (prev, next: Comment) => [next, ...prev]
  );

  async function onSubmit(formData: FormData) {
    const text = String(formData.get("text") || "");
    if (!text) return;

    // 1) UI 먼저 반영(낙관적)
    const temp = { id: `temp-${Date.now()}`, text };
    addOptimistic(temp);

    try {
      // 2) 서버 반영
      const saved = await createCommentOnServer(text);
      // 3) 실제 서버 결과로 state 확정(여기서는 단순히 prepend)
      setComments((prev) => [saved, ...prev]);
    } catch (e) {
      // 실패 시에는 toast + 재조회/롤백 전략이 필요
      // (낙관적 UI는 자동으로 원복되지 않으므로, 설계에 따라 처리)
      console.error(e);
    }
  }

  return (
    <div>
      <form action={onSubmit}>
        <input name="text" placeholder="댓글을 입력하세요" />
        <button type="submit">등록</button>
      </form>

      <ul>
        {optimisticComments.map((c) => (
          <li key={c.id}>{c.text}</li>
        ))}
      </ul>
    </div>
  );
}
```

### Form Actions (Actions)

React 19에서는 “폼 제출 → 비동기 처리” 흐름을 더 자연스럽게 만들기 위해 **Actions** 패턴이 강화되었다.  
핵심은 **`<form action={async (formData) => ... }>`**처럼 폼이 제출되면 실행될 함수를 “action”으로 붙여서 로직을 단순화하는 것이다.

- `onSubmit` + `preventDefault()`로 폼 이벤트를 직접 다루는 코드를 줄일 수 있음
- Progressive Enhancement(자바스크립트가 제한된 환경에서도 동작) 관점에서 유리한 설계가 가능

#### 예시 코드(폼 action)

```tsx
export default function Newsletter() {
  async function subscribe(formData: FormData) {
    "use server"; // (Next.js Server Actions 환경이라면)
    const email = String(formData.get("email") || "");
    // 저장/검증 로직...
  }

  return (
    <form action={subscribe}>
      <input name="email" placeholder="이메일" />
      <button type="submit">구독</button>
    </form>
  );
}
```

### useActionState (구 useFormState) / useFormStatus

폼 제출의 상태(진행 중 여부, 에러, 결과)를 다루기 위해 다음 훅들을 조합할 수 있다.

- `useActionState`: action의 결과(state)를 관리 (이전 이름이 `useFormState`로 알려진 경우가 많음)
- `useFormStatus`: 현재 폼 제출 상태(`pending`)를 읽어 버튼 disabled/로딩 표시 등에 사용

#### 예시 코드(제출 중 버튼 비활성화)

```tsx
import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "처리 중..." : "제출"}
    </button>
  );
}

export default function ContactForm() {
  async function send(formData: FormData) {
    "use server"; // Next.js Server Actions 환경 가정
    const message = String(formData.get("message") || "");
    // 저장/전송 로직...
    return { ok: true };
  }

  return (
    <form action={send}>
      <textarea name="message" placeholder="메시지" />
      <SubmitButton />
    </form>
  );
}
```

### use() / await Component 개선

React 19에서 `use()`는 **Promise**나 **Context** 값을 더 자연스럽게 꺼내 쓰기 위한 API이다.

- Promise를 `use()`로 읽는 경우 **Suspense 경계**가 필요
- 데이터 패칭을 “컴포넌트 트리”와 잘 맞물리게 표현 가능

#### 예시 코드(Promise + Suspense)

```tsx
import { Suspense, use } from "react";

type User = { name: string };

function fetchUser(): Promise<User> {
  return new Promise((resolve) =>
    setTimeout(() => resolve({ name: "tester" }), 300)
  );
}

function UserName({ userPromise }: { userPromise: Promise<User> }) {
  const user = use(userPromise);
  return <p>{user.name}</p>;
}

export default function Page() {
  const userPromise = fetchUser();

  return (
    <Suspense fallback={<p>Loading...</p>}>
      <UserName userPromise={userPromise} />
    </Suspense>
  );
}
```

### StrictMode 개선(체감 포인트)

StrictMode는 개발 환경에서 **부작용(side effect)**을 조기에 발견하기 위해 렌더/이펙트를 더 엄격하게 검사한다.

- “렌더는 순수해야 한다”를 강하게 요구(렌더 중 상태 변경/외부 변경 금지)
- 예상치 못한 이펙트가 있으면 개발 중 더 쉽게 드러남

#### 체크 리스트

- 렌더링 중에 API 호출/스토리지 접근/전역 값 변경 같은 작업을 하지 않기
- 사이드 이펙트는 `useEffect`(또는 서버/액션)로 이동
- 이벤트 핸들러에서만 상태 변경/요청을 수행하도록 정리

## 정리

- React Compiler: 최적화 부담을 줄이는 방향(도입은 빌드/프레임워크 상황에 따라)
- useOptimistic: 서버 응답 전에 UI를 먼저 업데이트하는 낙관적 UI
- Form Actions + useActionState/useFormStatus: 폼 제출 로직과 상태 관리를 더 선언적으로
- use(): Promise/Context를 Suspense와 함께 더 자연스럽게 소비
- StrictMode: 부작용을 빨리 찾기 위한 “더 엄격한 개발 모드”로 이해하면 좋음
