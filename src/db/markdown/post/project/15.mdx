크롬 플러그인(Chrome Extension)을 한 번 제대로 만들어보고 싶었다.  
단순히 "새 기술 찍먹"이 아니라, 실제 업무에서 반복되는 수동 작업을 줄일 수 있는지 검증해보고 싶었다.

회사 포털을 쓰다 보면 전직원이 반복하는 루틴이 있었다.  
예를 들어 `엑셀 다운로드 -> 양식에 맞게 수정 -> 복사 -> 전자결재 붙여넣기` 과정은 단순하지만 시간이 많이 들고, 실수도 자주 발생했다.

그래서 공부를 겸해, 이 반복 작업을 단축하는 목적의 사내용 크롬 플러그인을 직접 만들었다.

구현 내용은 [office-assistant-plugin](https://github.com/kwonyongjun1/office-assistant-plugin) 여기에 작성되어있다.

## 관련 개념 정리

### 크롬 플러그인 개발 시 필요한 것들

처음 시작할 때는 "웹앱과 비슷하겠지"라고 생각했지만, 실제로는 익스텐션 구조를 이해하는 게 중요했다.

- `manifest.json`: 확장 프로그램의 권한, 실행 컨텍스트, 스크립트 등록 정보
- `content script`: 포털 화면(DOM)에 접근해 데이터 추출/입력 자동화
- `background/service worker`: 이벤트 기반 작업 처리
- `popup/options`: 사용자 조작 UI
- 권한 설계: `activeTab`, `storage`, 특정 도메인 접근 권한 등

핵심은 기능을 많이 넣는 것보다, 필요한 권한만 최소로 열고 작업 흐름을 안정적으로 만드는 것이다.

### 회사 포털 자동화에서 중요했던 포인트

포털 자동화는 "기능 구현"보다 "환경 대응"이 더 중요했다.

- 로그인 상태 확인 로직
- DOM 변경에 대한 방어 코드
- 실패 시 재시도/알림 처리
- 민감정보를 로컬에 남기지 않는 정책

특히 로그인 후 발급된 토큰을 이용해 API를 호출하는 구조여서, 토큰 만료와 예외 처리 전략을 먼저 정해야 했다.

다만 사내 포털 내부 API 자체는 토큰 기반 인증 방식이 명확해서, 로그인 상태만 정상적으로 유지되면 호출 과정에서 큰 문제는 없었다.  
결국 구현 난이도보다 "토큰 만료 시점 처리"와 "실패 시 사용자 안내"를 어떻게 설계할지가 더 중요한 포인트였다.

### 기존 방식과 비교

| 구분        | 수동 처리                   | 플러그인 자동화            |
| ----------- | --------------------------- | -------------------------- |
| 작업 시간   | 사용자마다 편차 큼          | 단계 축소로 처리 시간 단축 |
| 실수 가능성 | 복사/붙여넣기 과정에서 잦음 | 규칙 기반 처리로 감소      |
| 확장성      | 사람 수 늘수록 비효율 증가  | 기능 추가로 범위 확장 가능 |

## 실제 적용

### 적용 전

- 업무 처리 흐름이 개인 숙련도에 크게 의존
- 반복 작업 시간이 누적되어 집중 시간이 끊김
- 양식 누락/오타 등 단순 실수가 발생

### 적용 방법

프로젝트는 사내 포털 중심 자동화를 목표로 다음 순서로 구성했다.

1. 포털의 반복 업무 흐름을 단계별로 분해
2. 크롬 익스텐션 구조(`manifest`, content script, popup) 설계
3. 포털 로그인 후 발급된 토큰으로 API 호출 로직 구성
4. 엑셀 데이터 처리 -> 전자결재 입력 단계 자동화
5. 실패 케이스(토큰 만료, DOM 변경) 예외 처리 추가

토큰 기반 API 호출은 아래와 같은 흐름으로 구현했다.

```ts
async function callPortalApi(endpoint: string, token: string) {
  const res = await fetch(endpoint, {
    method: "GET",
    headers: {
      Authorization: `Bearer ${token}`,
      "Content-Type": "application/json",
    },
  });

  if (!res.ok) {
    throw new Error(`Portal API error: ${res.status}`);
  }

  return res.json();
}
```

실무에서 느낀 점은, API 인증 구조 자체가 복잡해서 막히기보다는 로그인 세션과 토큰 상태를 안정적으로 유지하는 쪽이 실제 성공률에 더 큰 영향을 준다는 점이었다.

자동화 목표였던 업무 시나리오도 다음처럼 줄였다.

- 기존: 엑셀 다운로드 -> 양식 수정 -> 복사 -> 전자결재 붙여넣기
- 개선: 데이터 읽기/가공/입력 단계를 플러그인에서 일괄 처리

### 적용 후

- 반복 수작업 단계가 줄어 실제 업무 체감 시간이 단축됨
- 입력 포맷이 일정해져 문서 품질 편차가 감소
- 사용자가 "복붙 작업"보다 검토와 의사결정에 시간을 쓰게 됨

## 적용 후기

### 좋았던 점

- 궁금했던 크롬 플러그인 구조를 실무 맥락에서 학습할 수 있었다.
- 단순 자동화라도 팀 전체 누적 시간을 줄이는 효과가 분명했다.
- 작은 기능 단위로 릴리스하니 사용자 피드백을 빠르게 반영할 수 있었다.

### 아쉬웠던 점

- 포털 화면 구조가 바뀌면 자동화 로직이 쉽게 영향을 받았다.
- 권한/보안 정책을 지키면서 기능을 확장하는 데 제약이 있었다.
- 토큰 만료와 예외 처리 시 UX를 더 정교하게 다듬을 필요가 있었다.

## 마무리

이번 크롬 플러그인 개발은 "새 기술을 공부해보자"에서 시작했지만, 결과적으로는 반복 업무를 줄이는 실용적인 프로젝트가 됐다.  
앞으로도 실제 사용 데이터를 보면서 필요한 기능들을 계속 추가해, 사내 포털 업무를 더 안정적으로 자동화할 계획이다.
